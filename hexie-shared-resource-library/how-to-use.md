# hexie 操作规则

本文件给 `hexie-writer` 和 `hexie-check` 按需读取。SKILL.md 负责入口和流程，本文件负责可复用细则。

## 适用范围

适用：引言、导论、文献综述、理论铺垫、现实背景、研究背景、研究问题、研究缺口、边际贡献、贡献段，以及这些部分之间的开篇论证链。

不适用：数据处理、模型设定、实证结果、稳健性、机制检验、异质性、结论、政策建议。

## 阶段一问答模板

`hexie-writer` 阶段一使用以下模板引导用户构建判断链。每种论证类型一套问题链。

### 缺口驱动型

参考A论文：周黎安2007（理论悖论驱动）、余泳泽2019（数据悖论驱动）

```
首发问题：
"用一句话说清楚：你观察到了什么矛盾——什么现象是'按理说不该这样，但偏偏这样了'？"

→ 如果用户提到具体数据："能用1-2个数字让这个矛盾更尖锐吗？
   比如余泳泽2019写'服务业占比十年仅增2.1个百分点'——这个数字本身就在说'有问题'。"

后续问题链：
Q2: "现有的研究是怎么解释这个现象的？最有影响力的那个解释是什么？"
    → 用户回答后，writer 追问："这个解释哪里不够？是前提站不住脚，还是机制没讲清楚，
       还是解释不了某个关键事实？"

Q3: "那你的解释是什么？它为什么能补上前面说的那个不足？"

Q4: "在你之前，有没有人从类似角度想过？他们跟你最关键的区别在哪？"

Q5: "你的研究具体要回答哪几个问题？一个一个列出来。"

Q6: "你的发现主要贡献给哪支文献？——不只是'填补空白'，具体补充了什么？"
```

### 政策脉络型

参考A论文：林毅夫2020（消费券评估，识别挑战+三点贡献）

```
首发问题：
"你的研究针对的是哪个政策或外部冲击？什么时候发生的？"

后续问题链：
Q2: "这个政策/冲击的规模多大？有没有关键的数字能说明它的重要性？"
    → 用户说不清楚时，writer 上网搜。搜到了填入，搜不到标记待定继续。

Q3: "如果要评估这个政策的效果，最简单的方法是比较政策前后的变化。
     但如果有人质疑'这个比较不公平，因为……'，他会怎么说？"
    → 引导用户自己说出识别挑战。如果用户说不上来，writer 搜索该领域的
       相关实证论文，看2-3篇怎么处理识别问题，结合这一步的结构展示选项。

Q4: "你用什么方法来解决刚才说的这些问题？"
    → 用户回答后，writer 追问："每个方法对应解决哪个问题？"

Q5: "你的核心发现是什么？不一定非要三点，先说最重要的那个。"

Q6: "你的发现对三支文献分别有什么贡献：(a)这个政策所属的领域——
     你的发现补充了什么空白？(b)政策评估方法论——你的做法跟已有研究有什么不同？
     (c)更大的理论框架——你的发现对什么理论有什么含义？"
```

### 机制推导型

参考A论文：赵岳2011（电商平台信贷，理论模型）、余淼杰2010（贸易自由化与生产率，方法论驱动）

```
首发问题：
"你要解释的现实问题是什么？这个问题为什么重要？"

后续问题链：
Q2: "最近出现了什么新做法、新技术或新制度，可能改变这个问题？
     不用术语，就像跟同事聊天一样，说说它具体怎么运作的。"

Q3: "如果它真的有用，通过哪几个渠道起作用？先不急着建模，把可能性都列出来。"

Q4: "要检验这些渠道，最大的方法论障碍是什么？
     → 余淼杰2010花了半篇引言讲TFP的三个测量偏差。如果你的研究也有类似的基础度量问题，
       把它变成引言的结构——每个测量问题对应一个解决方案。"

Q5: "你怎么验证这些渠道真的在起作用？用什么方法或模型？"
```

### 主题线分组型

参考A论文：马述忠2021（跨境电商，文献双线+三点创新+政策表格）

```
首发问题：
"你的研究涉及哪两支文献或哪两个领域？它们各自在说什么？"

后续问题链：
Q2: "这两支文献有没有互相引用、互相讨论？还是各说各的？"

Q3: "它们在哪一点上应该对话，但从来没对过？"

Q4: "你把它们放在一起，得出了什么单独看哪一支都得不出的结论？"
```

## 事实来源优先级

现实背景事实必须核验：

- 政策法规：政府官网、正式政策文本、监管公告。
- 统计数据：国家统计局、海关总署、Wind、CSMAR、CNRDS、WIPO、World Bank、OECD、IMF、UNCTAD 等。
- 国际事件与产业背景：官方公告、国际组织、顶刊论文、NBER/CEPR working paper、权威研究报告。
- 企业案例：企业公告、年报、监管文件、权威数据库或正式新闻稿。

文献事实必须回到用户提供的原文、PDF、MD、参考文献材料，或可靠检索结果。A分类句子卡片和 B分类段落骨架都不能作为事实依据。

## 事实验证分层

验证时先分层，避免重复联网：

| 验证层级 | 适用情况 | 处理方式 |
|----------|----------|----------|
| 用户材料已验证 | 用户已提供原文/PDF/MD/参考文献，且事实可在材料中确认 | 优先本地核验，不重复联网 |
| 本地可用但需补出处 | 本地材料能支持判断，但缺页码/DOI/链接 | 可继续，标为"可用但需补出处" |
| 可靠检索已验证 | 新增文献或背景事实已由官方来源/权威数据库/顶刊/高质量 WP 验证 | 可作为依据，记录来源层级 |
| 待用户补充 | 事实可能成立但当前无足够依据 | 标为"待验证"，暂停终稿 |
| 无法验证 | 联网不可用且本地无依据，或检索结果互相冲突 | 标为"待验证/阻塞" |

新增文献或背景事实必须进入"可靠检索已验证"或"待用户补充/无法验证"，不能因为表达顺畅就通过。

## 开篇组织方式

| # | 方式 | 识别特征 |
|---|------|---------|
| 1 | 主题线分组 | 按两类或多类研究主题组织 |
| 2 | 概念论证块 | 每小节处理一个概念部件，合起来推导假说 |
| 3 | 缺口驱动型 | 现象悖论→现有解释→逐层反驳→替代框架 |
| 4 | 机制推导型 | 现实创新→自然语言机制→理论模型 |
| 5 | 对比型 | 按对立观点组织，指出分歧和证据 |
| 6 | 政策脉络型 | 外生冲击→政策回应→识别挑战→方法策略 |
| 7 | 时间演进型 | 按现实或研究的发展阶段组织 |
| 8 | 概念辨析型 | 围绕概念定义、边界和演变组织 |

## 素材读取规则

writer 使用共享资源库时，先读 `index.md`，按两层分工取用：

- **B分类（论证骨架）**：按论证类型分类的判断链 + 段落功能分析。阶段一搭论证骨架时，取匹配类型的骨架看判断链推进。
- **A分类（论文全文）**：已解剖的论文完整MD，对应B分类骨架。阶段三写完文本后，拿产出与对应A论文引言对照比较语言质量。

事实核验：任何素材都不能作为事实依据。

## 写作和选文献规则

- 默认篇幅：用户未规定字数时，正文默认不少于 800 字；用户明确要求只改局部时除外。
- 判断先行：句子主干先构成学术判断，再用事实或引用提供证据。
- 背景克制：现实背景只服务于研究问题，不写新闻综述或政策罗列。
- 引用简洁：括号里只写作者和年份；正文只写与论证有关的发现。
- 关系诚实：不虚构递进、不假造对话、不把并列文献写成因果链。
- 语言自然：避免 AI 腔。

按"关系角色"补文献：缺反面证据找相反发现，缺中间机制找渠道文献，缺最新证据找近两年研究，缺中国情境找中国数据文献。

来源优先级：
1. 国内五大与中文顶刊：`经济研究`、`管理世界`、`中国工业经济`、`世界经济`、`金融研究`，及领域权威 CSSCI 期刊。
2. 国外顶刊：AER、QJE、JPE、Econometrica、ReStud、Management Science、SMJ、ASQ、AMJ、JIBS 等。
3. 高质量工作论文：NBER、CEPR、SSRN；必须标明 working paper 状态。
4. 普通期刊、硕博论文、媒体材料只作补充，不作为核心文献。

## 英文引用处理

- 英文文献在正文中可写为"Author 和 Author（年份）"或"Author 等（年份）"；已有通行中文译名或用户指定译名时，才使用中文作者名。
- 括号引用保持作者-年份简洁，不主动加入期刊名、国家、数据库、模型或方法细节，除非这些信息本身承担论证功能。
- 两位作者用"和"连接；三位及以上用"第一作者等（年份）"；机构作者保留机构名。
- working paper 首次出现时注明"工作论文"或"NBER working paper"；不能写成正式发表论文。
- 英文文献发现的方向、对象、机制和适用条件必须按原文核验，不因翻译而改变含义。

## 文献核验（writer 阶段二调用）

引用核验调用 `reference-verifier` 或当前环境可用的联网核验能力。核验必须完整可审计：若声称核验 N 条引用，逐条核验表必须列出 N 条，每条至少包含正文表述、判定状态、依据 URL/DOI 和判定理由。

核验状态：
- `METADATA_VERIFIED` — 文献存在确认，方向仍需自行判断
- `ABSTRACT_DIRECTION_VERIFIED` — 正文仅说"该文研究了X主题"时可过
- `CLAIM_SUPPORTED` — 正文的具体说法能被摘要/全文明确支持
- `NOT_FOUND` / `MISMATCH` / `CLAIM_TOO_STRONG` — 致命，不得通过
- `AMBIGUOUS` / `NO_ACCESS` / `NETWORK_UNAVAILABLE` — 待验证

材料不足模式：若用户未提供原文/PDF/MD/参考文献材料，writer 阶段二只能标"待验证"，不得判定"通过"。此时 writer 阶段三只能输出"待核验稿"。
