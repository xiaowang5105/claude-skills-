# 文献综述质量检查

本 skill 对文献综述进行质量检查，输出检查报告。不自动修改文本。独立运行，用户收到报告后自行决定是否修改。

**⚠️ 铁律：不得无中生有。任何一处引用，如果改写了原文献的核心发现方向、编造了原文献没有的结论、或把作者没有的意思强加进去 → 直接不合格，无须继续检查。**

范例目录：`~/.claude/skills/hexie/examples/`，按八种组织方式分文件，每个文件头部有索引表。

---

## 执行流程

**Step 1. 读全文，定位文献综述段落。**

**Step 2. 识别该文献综述的组织方式**（八选一）：

| # | 方式 | 识别特征 |
|---|------|---------|
| 1 | 主题线分组 | "与本文相关的第一类文献…第二类文献…" |
| 2 | 概念论证块 | 每小节一个概念部件，拼起来推假说 |
| 3 | 缺口驱动型 | 累积成果→局限→转移焦点→结构缺口→整合 |
| 4 | 机制推导型 | 以"X通过什么渠道影响Y"为纲 |
| 5 | 对比型 | 按对立观点组织，指明分歧点和证据 |
| 6 | 政策脉络型 | 沿政策演变组织 |
| 7 | 时间演进型 | 按发展阶段组织 |
| 8 | 概念辨析型 | 围绕概念定义演变组织 |

**Step 3. 打开对应组织方式的范例文件，先读索引表定位范例，再逐段通读。**

---

**Step 4. 逐条检查以下清单，标记违规。** 三组共13条，无重复。

### 结构组（段落层面的组织方式）

- [ ] **1. 引用位置**：逐段数句首引用数。奠基性学者（首次定义概念/给出首个证据）可豁免，但每段最多一处。每段句首引用数 ≥ 2 → 违规。
- [ ] **2. 段首写法**：每段第一句去掉括号引用后是否构成完整学术判断？不成立或以作者名开头 → 违规。
- [ ] **3. 转折后判断先行**："然而""与之相反"之后，判断在前还是证据在前？证据在前 → 违规。
- [ ] **4. 连接词密度**：每200字关联词数（然而/此外/从而/进而/换言之/由此等）。任意段 < 3 → 违规。
- [ ] **5. 收束句**：每段尾句是否有收束功能（总结/指出不足/过渡/提出含义）？以引用发现结尾无判断、以描述结尾无推进 → 违规。

### 语言组（句子层面的表达规范）

- [ ] **6. 标点**：是否出现破折号（——）或冒号（：）？破折号每段 > 1次 → 违规。
- [ ] **7. 叙述主体**：是否出现"我们""我""笔者"？是 → 违规。
- [ ] **8. AI腔**：是否出现"随着...的发展""具有重要的理论意义和实践意义""在一定程度上""较为""鲜有研究探讨""有待进一步研究""值得注意的是"？是否出现元评论式宣告"两条独立传统""这一差异的理论基础来自""争议在于""以下将从X个方面展开"？是 → 违规。
- [ ] **9. 引用简洁**：是否有"XX（2020）利用XX数据研究了XX，发现……"？有 → 违规。
- [ ] **10. 语病**：逐句朗读，主谓搭配不当/宾语残缺/修饰语错位/句式杂糅/"的地得"混用/指代不明 → 违规。
- [ ] **11. 句间节奏**：连续5句以上字数相近（偏差<5字）？最短句与最长句差 < 30字？≥15字句子连续堆砌无短句断开？任一 → 违规。

### 忠实组（原文准确性）

- [ ] **12. 词汇来源**：提取承载学术含义的内容词（动词、名词、评价性形容词/副词），逐一比对 hexie-writer 词汇库。不在库中 → 替换为库中同类词，或联网验证该词在本领域顶刊的实际使用。未替换且未验证 → 违规。
- [ ] **13. 终极检验**：删掉所有引用和括号，剩文是否为逻辑连贯的学术小品？否 → 违规。

---

**Step 5. 核对原文含义。** 逐条引用对比原文，检查改文是否扭曲了任何一篇原文献的发现含义。重点检查三个维度：方向（正向/负向/非线性是否一致）、内容（发现的具体机制/效应是否被改写）、归属（发现是否确实来自该文献而非张冠李戴）。任何一处被改写了核心发现或结论方向 → 直接不合格，无须进入 Step 6。

**Step 6. 联网验证 + 逻辑检验。**

1. **联网验证内容**：逐条检索关键文献的核心发现，确认改文表述与原文一致。本步是 Step 5 的兜底——Step 5 靠阅读比对，本步靠实际检索。
2. **逻辑链检验**：将段落内每句压缩为短语（A→B→C→D），看链是否完整。如果缺环节，标记为逻辑跳跃。

两项任一不通过 → 直接不合格。

**Step 7. 生成检查报告，格式见末尾。**

---

## 检查报告格式

```
# 文献综述质量检查报告

**文件**：[文件名]
**组织方式**：[方式名]
**检查时间**：[时间]

## 检查清单

| # | 检查项 | 组 | 结果 | 详情 |
|---|-------|----|------|------|
| 1 | 引用位置 | 结构 | ✓/✗ | |
| 2 | 段首写法 | 结构 | ✓/✗ | |
| 3 | 转折后判断先行 | 结构 | ✓/✗ | |
| 4 | 连接词密度 | 结构 | ✓/✗ | |
| 5 | 收束句 | 结构 | ✓/✗ | |
| 6 | 标点 | 语言 | ✓/✗ | |
| 7 | 叙述主体 | 语言 | ✓/✗ | |
| 8 | AI腔 | 语言 | ✓/✗ | |
| 9 | 引用简洁 | 语言 | ✓/✗ | |
| 10 | 语病 | 语言 | ✓/✗ | |
| 11 | 句间节奏 | 语言 | ✓/✗ | |
| 12 | 词汇来源 | 忠实 | ✓/✗ | |
| 13 | 终极检验 | 忠实 | ✓/✗ | |

## 违规详情

[列出所有标记为✗的检查项及具体位置]

## 引用准确性（错引/无中生有/曲解原意）

| 引用 | 原文发现 | 改文表述 | 方向一致 | 内容一致 | 归属正确 |
|------|---------|---------|:--:|:--:|:--:|
| XX（年份）| ... | ... | 是/否 | 是/否 | 是/否 |

**任一"否"→直接不合格。后续流程取决于此表结果：**

### 全表通过 → 进入终稿输出

全部引用三项均为"是" → 报告通过。自动生成两个文件：
1. `原文件名_终稿.md` — Markdown格式，含正文+参考文献
2. `原文件名_终稿.docx` — Word格式，通过pandoc转换

两个文件保存在同一目录下。

### 有"否" → 输出修正清单，不输出终稿

报告末尾附一张**修正清单**，格式：

```
## 修正清单（带回 hexie-writer 定点修正）

| 引用 | 问题类型 | 具体问题 | 修正建议 |
|------|---------|---------|---------|
| XX（年份）| 方向不一致 | 原文说抑制，改文说促进 | 改为"抑制" |
| YY（年份）| 内容改写 | 原文说的是机制A，改文写成了机制B | 改为机制A的准确表述 |
| ZZ（年份）| 归属错误 | 这个发现是AA(2021)的，不是ZZ的 | 引用改为AA(2021) |
```

用户带着这张修正清单回到 hexie-writer，**只修正清单列出的引用，不改其他内容**。修正后再次运行 hexie-check **完整流程**（13条清单+引用准确性），确认修改未破坏其他已达标项。

---

**重要：检查报告之后，必须附上被检查的完整文本内容。** 格式：

```
## 检查通过的文本

[被检查的完整文献综述文本]
