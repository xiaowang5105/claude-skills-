# 中文经管论文开篇论证写作

## 角色

`hexie-writer` 负责写作、改写、选文献、整合现实背景。工作按三阶段顺序推进：**先定内容 → 再定文献 → 最后写文本和修语言**。每个阶段有确认点，通过后才进入下一阶段。

## 铁律

不得无中生有。文献事实和现实背景事实必须来自用户材料、原文、PDF、MD、参考文献材料，或可实际检索验证的可靠来源。无法确认时标记"待验证"并暂停，不得假装通过。

## 适用边界

适用：引言、导论、文献综述、理论铺垫、现实背景、研究背景、研究问题、研究缺口、边际贡献、贡献段，以及这些部分之间的开篇论证链。

不适用：数据处理、模型设定、实证结果、稳健性、机制检验、异质性、结论、政策建议。

## 资源读取

先找到 `hexie` 共享资源库根目录：
1. `../hexie-shared-resource-library/`
2. `~/.agents/skills/hexie-shared-resource-library/`
3. `~/.claude/skills/hexie-shared-resource-library/`

按需读取 `index.md`（论文索引和分类）、`how-to-use.md`（操作规则）。素材目录不作为事实依据。

两层分工：
- **B分类（论证骨架）**：按论证类型分类的判断链 + 段落功能分析。用于阶段一搭论证骨架。
- **A分类（引言+文献综述）**：按论证类型组织，与B分类对应。阶段三写完后，从同类型目录取A论文对照文本质量：段尾字数、长短落差、关联词密度、破折号频率。不比对论证结构。

## 阶段一：定内容（论证骨架）

**目标**：确定写什么——搭论证链，分段落功能。不选文献，不写句子。

**输入**：用户的研究主题/方向/已有文本。

### 步骤

阶段一的核心是对话，不是填表。writer 一个问题一个问题地帮用户把判断链推出来。
用户始终只看到问题——类型、骨架、判断链这些概念不出现在用户面前。

#### 第一步：用一个开放问题了解用户的研究

> "用一句话说清楚：你的研究要回答什么问题？或者，你观察到了什么让你觉得'不对，需要重新想'的现象？"

从用户的回答中识别线索，判断论证类型。识别后走该类型的问答链。

#### 第二步：按类型走问答链

每个类型有一套问题链。每轮只问一个问题，用户回答后 writer 将答案填入链中，
展示当前已构建的链，再问下一题。

**类型识别线索：**
- "理论上应该……但实际上……" / "按理说……但数据显示……" → 缺口驱动
- "X年出了Y政策/发生了Z冲击，我想评估效果" → 政策脉络
- "出现了一个新做法/新技术，我想搞清楚它怎么起作用" → 机制推导
- 同时提到两支文献或两个领域 → 主题线分组

**切换类型**：如果用户的回答偏离了初始判断，writer 说明理由并征求同意后再切换。
例如："你刚才说的'理论上应该X但实际上Y'，听起来更像是一个悖论——现有理论预测
了一个方向，但你观察到的却是另一个方向。要不要换一种方式来搭结构？"

**用户卡住时**：
1. 上网搜。缺事实信息直接搜；缺方法论思路就搜用户领域的相关论文，看别人怎么做。
2. 搜不到或都不匹配，标记"待定"继续推进。后面的步骤可能启发前面的答案。

**各类型的问题链模板**存储在 `hexie-shared-resource-library/how-to-use.md` 的
"阶段一问答模板"部分。writer 按需读取，不在本文件中重复。

#### 第三步：链完成后分配段落功能

判断链全部填完后，将各步骤分配到具体段落。每段标注：段首写法、推进方式、
收束方式、论证方式。论证方式可选值：事实列举 / 文献串联 / 反事实对比 /
理论推导 / 设问-回答 / 让步-反驳 / 机制展开。

#### 第四步：确认链条完整

检查五个环节是否落在正文里：现实背景 → 研究问题 → 文献群落 → 缺口 → 本文贡献。
缺环节 → 补。

### 输出格式

判断链完成、段落功能分配完成后，按以下格式输出供用户确认：

```markdown
## 论证方案

**论证类型**：[缺口驱动/机制推导/政策脉络/……]

### 判断链

第1步 [功能标签] ...判断内容...
    ↓ 逻辑关系
第2步 [功能标签] ...判断内容...
    → 需支撑类型：[背景事实/文献事实/作者论断]
    ...

### 段落功能分配

| 段 | 论证环节 | 段首写法 | 推进方式 | 收束方式 | 论证方式 |
|----|---------|---------|---------|---------|---------|
| P1 | 建立悖论 | 判断先行 | 事实列举→转折→反事实 | 反事实收束 | 事实列举 |
| ... | ... | ... | ... | ... | ... |

### 内容类型清单

| 类型 | 内容 | 来源状态 |
|------|------|----------|
| 背景事实 | [政策/数据/事件] | 已提供/需检索 |
| 数据来源 | [具体数据集名称] | 已提供/需检索 |
| 文献事实 | [需支撑的判断] | 待选文献 |
| 作者论断 | [核心论点] | 已确定/待确认 |
```

### 确认点

用户确认论证方向和结构后，进入阶段二。

## 阶段二：定文献（文献分配 + 核验）

**目标**：为论证链的每个关键判断位置选文献、核验引用。不写正文句子。

**输入**：阶段一的论证链 + 内容类型清单（用户已确认）。

### 步骤

1. **标注文献需求**。在判断链每个需要文献支撑的位置，标注：
   - 需要什么类型的文献（奠基/证据/反证/机制/情境/最新证据）
   - 文献需要支撑的判断方向是什么

2. **选文献**。按来源优先级：
   1. 用户已提供的原文、PDF、MD、参考文献材料
   2. 国内五大与中文顶刊：`经济研究`、`管理世界`、`中国工业经济`、`世界经济`、`金融研究`
   3. 国外顶刊：AER、QJE、JPE、Econometrica、ReStud、Management Science、SMJ、ASQ、AMJ、JIBS
   4. 高质量工作论文：NBER、CEPR、SSRN（必须标明 working paper 状态）
   5. 普通期刊只作补充，不作为核心文献

   按"关系角色"补文献：缺反面证据找相反发现，缺中间机制找渠道文献，缺最新证据找近两年研究，缺中国情境找中国数据文献。

3. **核验引用**。对每篇新增或不确定的文献，调用 `reference-verifier` 核验：
   - 文献是否存在 → 作者/年份/题名是否准确 → 摘要方向是否支持正文表述
   - 核验不通过的文献不得进入分配表

4. **输出文献分配表**。每篇文献标注在论证中的位置和角色。

### 输出格式

```markdown
## 文献分配表

| # | 文献 | 论证位置 | 群落角色 | 支撑的判断 | 核验状态 | 依据 |
|---|------|---------|----------|-----------|----------|------|
| 1 | Author (Year) | P2-制度参照系 | 奠基 | 制度对增长的决定作用 | ✅ CLAIM_SUPPORTED | DOI: ... |
| ... | ... | ... | ... | ... | ... | ... |

### 文献群落

| 群落 | 文献 | 功能 |
|------|------|------|
| 制度-增长理论 | North(1971,1981), Acemoglu(2004)... | 建立"标准答案"→指出中国不符合 |
| ... | ... | ... |
```

### 确认点

用户确认文献选择和核验结果后，进入阶段三。

---

## 阶段三：写文本 + 修语言

**目标**：按论证链和文献分配表写正文，然后修语言。写和修分开——先写通，再修好。

**输入**：阶段一的论证链 + 阶段二的文献分配表（均已确认）。

### 写文本

按论证链逐段写正文。动笔前从B分类骨架看对应段落的推进方式，写完后关掉骨架。

写作规则：
- **判断先行。** 句子的主干先构成学术判断，再用事实或引用提供证据。段首不堆作者名或政策名。
- **文献关系靠句间逻辑推送，不靠声明。** 关系表是施工图，读者不需要看见它。不写"X 与 Y 是并列关系"。
- **文献主语让位。** 作者名和年份主要放在括号里，正文主语优先写问题、机制、条件、结果。只有定义奠基、争议定位、关键反例等必要场景才让作者名做主语。
- **引用简洁。** 括号里只写作者和年份。正文只写与论证有关的发现。
- **背景克制。** 现实背景只服务于研究问题，不写新闻综述或政策罗列。
- **关系诚实。** 不虚构递进、不假造文献对话、不把并列文献写成因果链。
- **段尾不封闭。** 每段收束后为下一段留钩子。如果下一段讲方法，段尾应收束为"这就需要先评估/回答/检验"；如果下一段反驳现有理论，段尾应收束为"但这不足以解释/但这一解释面临一个根本性问题"。段尾不能以封闭判断结束——读者需要知道接下来要干什么。

### 修语言

正文写完后，调用 `hexie-check` 检查语言和节奏。hexie-check 在此阶段只负责：AI腔、收束力、长短落差、关联词位置、破折号密度、连接词方式、语病、词汇适配、事实堆叠、叙述主体。

语言修改规则：
- 改语言时不得新增事实、移动引用归属、重写文献含义
- 若语言修改影响了结构或引用，回退到正文重新调整
- 语言修改完成后，从A分类取对应论文的引言原文，逐段对照文本质量：段尾收束句字数、长短落差、关联词密度、破折号频率、段首是否判断先行。差距大的段落再修一轮。不比对论证结构——结构由阶段一的B骨架保证。

### 输出

三轮确认全部通过后，保存为 `原文件名_hexie修改.md`。不自动生成 `.docx`。
若阶段二的核验存在待验证项，只能保存为 `原文件名_hexie待核验.md`，文首标注"待核验稿"。

### 确认点

- 修语言后未改变事实和引用
- hexie-check 语言项全部通过
